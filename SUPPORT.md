# Support Policy

WelcomeScore is maintained as an ETHIOR project. This policy explains where to ask for help and how to protect other users while doing so.

## Where to ask

Use the canonical [WelcomeScore repository](https://github.com/ethiorhq/welcomescore) for public, non-sensitive support questions about using the audit, interpreting documented score signals, contributing code, badges, the Hall of Fame, or the Dev Lounge.

Before opening a new issue, search existing issues and read the README, [FAQ](https://welcomescore.vercel.app/faq), [How It Works](https://welcomescore.vercel.app/how-it-works), and [CONTRIBUTING.md](CONTRIBUTING.md). A focused report is easier for maintainers and other contributors to understand.

## Do not post sensitive information

Do not include API keys, access tokens, passwords, cookies, private keys, private repository URLs, personal data, financial information, unpublished vulnerabilities, or harmful content in public GitHub issues, pull requests, comments, or the Dev Lounge.

For a suspected security issue, follow [SECURITY.md](SECURITY.md). For a conduct concern, follow [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). The Dev Lounge is not a private support channel and is not suitable for account recovery, security reports, commercial offers, legal advice, or emergency assistance.

## What maintainers can help with

Maintainers may help clarify documented behavior, reproduce a product issue, review an appropriately scoped proposal, or direct you to the right project resource. They may not be able to provide individual consulting, legal advice, financial advice, account administration for third-party services, guaranteed response times, or support for modified forks.

WelcomeScore scores documented public repository signals; it does not certify a repository, contributor, maintainer, employer, service provider, transaction, or business relationship. Use the results as a practical prompt for further review, not as a guarantee or recommendation.

## Respectful participation

Please keep questions concise, constructive, and relevant. Follow the Code of Conduct, avoid repeated requests, and do not pressure volunteers for immediate responses. Contributors and maintainers are not obligated to respond to every request.
